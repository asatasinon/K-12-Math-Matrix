# K-12 Math Matrix Roadmap

## 1. 路线图原则

路线图按 3 个阶段设计：

- 阶段一：从 0 到 1，先把平台基础能力跑通
- 阶段二：从 1 到 10，提升内容规模和生产效率
- 阶段三：从 10 到 100，做成可持续扩展的平台

顺序不能颠倒。没有稳定的内容模型、审核流和搜索体系，就不应该提前做复杂个性化。

## 2. 阶段一：MVP（0-1）

时间目标：8 到 12 周

阶段目标：

- 建立可运行的学生前台和教研后台
- 跑通知识点创建、审核、发布闭环
- 支撑课标主干 + 竞赛支线的基础建模
- 上线首批内容并验证检索与图谱体验

核心交付：

- 学生前台：首页、课程树、知识点详情页、搜索页
- 教研后台：知识点编辑、关系编辑、审核中心
- 后端服务：FastAPI API + Celery Worker
- 基础服务：PostgreSQL、Redis、Meilisearch、RustFS
- 内容能力：理论、公式、案例、技巧、静态图、少量交互图、视频嵌入
- AI 能力：知识点初稿生成、基础质检

内容里程碑：

- 完成一个可展示的学段样板，例如“小学高年级 + 初中几何”
- 每个样板至少覆盖 100 到 200 个知识点
- 课标主干与竞赛支线均有可见内容

技术里程碑：

- 前端与 Python 后端共仓结构初始化完成
- 前后端分离部署完成
- 搜索索引可稳定更新
- 发布态内容可被前台读取

退出标准：

- 一个知识点详情页可稳定展示完整结构化内容
- 编辑到审核到发布流程闭环可用
- 搜索可按多个维度组合筛选
- 图谱可展示知识点邻接关系

主要风险：

- 内容模型不够稳定，导致后续返工
- AI 初稿质量不稳定，拖慢人工效率
- 关系维护成本被低估

## 3. 阶段二：规模化（1-10）

时间目标：3 到 6 个月

阶段目标：

- 将平台从样板区域扩展到更多年级和模块
- 提升内容生产效率和后台可用性
- 让学生前台具备更强的专题和路径能力

核心交付：

- 专题页与学习路径页
- 更完善的关系编辑器
- 批量导入与批量生成能力
- 更细的内容质量报表
- 媒体中心与资源复用能力

内容里程碑：

- 覆盖完整小学与初中主干知识树
- 高中核心模块开始系统化建设
- 竞赛内容形成明确专题分组

技术里程碑：

- AI 任务拆分与重试机制成熟
- 搜索相关性优化
- 缓存与异步任务体系稳定
- 监控指标与审计日志完善

退出标准：

- 内容生产效率明显高于纯人工流程
- 多个年级内容可以持续稳定发布
- 前台专题学习与搜索体验可支撑真实用户使用

主要风险：

- 内容规模扩大后审核能力不足
- 搜索质量不一致，影响内容可达性
- 媒体资源开始堆积，缺乏治理

## 4. 阶段三：平台化（10-100）

时间目标：6 到 12 个月

阶段目标：

- 将平台从“内容站”升级为“学习平台”
- 引入学习行为、推荐和更细的协作体系
- 建立可持续扩展的产品和工程能力

核心交付：

- 个性化推荐和学习路径排序
- 用户学习记录与收藏体系
- 更丰富的数学实验型交互内容
- 更细粒度的组织和角色管理
- 更成熟的部署、监控和容灾能力

内容里程碑：

- 高中主干知识树基本完整
- 竞赛专题形成体系化库
- 难度分层与专题组合能力成熟

技术里程碑：

- 部署体系从 Compose 升级到容器编排
- 搜索和推荐形成协同
- 内容版本与审计能力支持多人协作

退出标准：

- 内容、搜索、图谱、媒体、审核、推荐形成完整平台能力
- 新增学科或新专题时无需重写底层系统

主要风险：

- 个性化建设早于内容质量成熟
- 组织协作复杂度上升
- 运维体系跟不上平台复杂度

## 5. 优先级排序

始终保持以下优先级：

1. 内容模型正确
2. 发布流程可靠
3. 搜索与图谱可达
4. 内容规模扩张
5. 个性化与高级运营能力

## 6. 非目标

本路线图默认不把以下事项列为前两阶段目标：

- 原生 App
- 自建视频转码平台
- 重型题库和组卷系统
- 复杂机构版多租户系统
- 竞赛训练营式运营功能

## 7. 管理建议

每个阶段都建议同时维护 3 条看板：

- 产品功能看板
- 内容建设看板
- 工程稳定性看板

只有三条线同步推进，这个平台才不会变成“有页面没内容”或“有内容没系统”的半成品。
